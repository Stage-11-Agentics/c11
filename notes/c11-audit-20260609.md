# c11 Audit — 2026-06-09

Full-repo audit (10 parallel research agents, all findings verified by reading code; empirical checks noted). Each bullet is scoped so a model can fix it without re-deriving context. Severity: **H**igh / **M**ed / **L**ow. `(spec)` = speculative, verify before fixing.

Verified live: without `CMUX_SOCKET_PATH` exported, `c11 ping` fails against a running app. Any context outside a c11 pane (cron, launchd, fresh shells) is dead. Also fix the DEBUG default `/tmp/cmux-debug.sock` (`c11.swift:1459`) and the Sentry diagnostics scan that only matches `cmux*.sock` (`c11.swift:283-302`).
- [H] **The binary never exports the `C11_*` env vars the skills document.** Surfaces only get `CMUX_SURFACE_ID/WORKSPACE_ID/TAB_ID/SOCKET_PATH/SHELL_INTEGRATION` (`Sources/GhosttyTerminalView.swift:3339-3412`). Verified live: `C11_SHELL_INTEGRATION` etc. are unset inside c11, so `skills/c11/SKILL.md:19-48` detection and every `--surface "$C11_SURFACE_ID"` example expands empty and now errors (0.51.0 rejects empty refs). Either export `C11_*` mirrors in the binary (preferred per naming convention) or rewrite the skills. - [H] **`C11_AGENT_TYPE`/`C11_AGENT_MODEL`/`C11_AGENT_TASK` don't exist anywhere in the codebase** yet `skills/c11/SKILL.md:43-48` + `references/api.md:56-58,195` tell agents to trust them; the canonical `c11 set-agent --type "$C11_AGENT_TYPE"` call fails (`--type` required, `CLI/c11.swift:11141`). - [H] **`pane.confirm` beachballs the whole app.** It's not in `socketWorkerV2Methods` (`TerminalController.swift:1811`), so it runs under `DispatchQueue.main.sync`, then `semaphore.wait` on main (`:9665`) for a dialog only the blocked main thread could answer.
