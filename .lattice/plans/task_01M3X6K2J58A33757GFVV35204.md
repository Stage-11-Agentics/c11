## What publishes a spinner

`GHOSTTY_ACTION_SET_TITLE` (`Sources/GhosttyTerminalView.swift:2219-2234`) turns every OSC title, including a spinner frame, into `.ghosttyDidSetTitle` on the next main turn. Three observers receive it:

- `WorkspaceManager` (`:1141-1151`) enqueues `enqueueTabTitleUpdate` (`:3467-3474`). The coalescer is 30 Hz (`:1065`). `flushPendingPanelTitleUpdates` (`:3477-3483`) still applies each distinct string through `TabMetadataStore.setMetadata` (`:3506-3511`, source `.osc`) and, for the focused tab, `updateWindowTitle` (`:3522-3524`).
- `ContentView` (`:2612-2615`) schedules a titlebar refresh.
- `WindowToolbarController` (`:35-41`) schedules the toolbar label.

The ticket's `SurfaceMetadataStore` citation is `TabMetadataStore` after the rename. `WorkspaceManager.swift:1065` matches. Do not touch `GHOSTTY_ACTION_PWD` (`:2237`), the scroll cases above this one, or the coalescer interval.

## Window title is not the OSC string

`updateWindowTitle` (`WorkspaceManager.swift:3546-3559`) writes `NSWindow.title` from `workspace.title`. That is the workspace name, or the directory, or the fallback `"cmux"`. `focusedSurfaceTitleDidChange` (`:3527-3534`) would copy a tab title in through `Workspace.applyProcessTitle` (`Workspace.swift:6666-6669`), and nothing calls it. A focused OSC apply still reassigns `window.title` to the same workspace string. The tab label is the metadata title, applied in `syncTabTitleFromMetadata` (`Workspace.swift:7255-7285`).

This PR does not route OSC text into `workspace.title`. Spinner frames stop causing that reassignment and stop changing the tab label. A real title still changes the tab label. The window title stays the workspace title.

## Change

Add `Sources/TerminalTitleChurnFilter.swift`, a pure type with no AppKit.

`shouldPublish(previous:next:)`:

- Trim both. A trimmed-empty `next` is a clear. Publish it when `previous` has meaningful text. Do not invent a name for an empty title.
- A non-empty `next` whose text is empty once spinner glyphs are removed is spinner-only. Drop it. Do not clear the previous title.
- Otherwise drop when meaningful texts are equal, recognizing standalone frame tokens at word boundaries around unchanged words. Preserve adjacent glyph runs as text/art, including a Braille word, following upstream’s false-positive guard. Do not delete glyphs embedded inside meaningful text (for example A·B versus AB); preserve such real title changes.
- Otherwise publish the raw `next`, not a rewritten string. `"claude ◐"` after `"zsh"` publishes once. The next frame `"claude ◓"` drops.

Glyphs, and only these:

- Braille spinner: `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` and `⣷⣯⣟⡿⢿⣻⣽⣾`
- Asterisk frames: U+2731–U+273D (`✱✲✳✴✵✶✷✸✹✺✻✼✽`), plus Claude marks `✢` and `·`
- Half-circles: `◐◓◑◒` (U+25D0–U+25D3). Include quadrant circles U+25F4–U+25F7 (`◴◵◶◷`) from upstream as well. A braille-only set misses circle spinners.

Do not strip ASCII `|/-\`, block glyphs (`█▓▒░`), or the rest of the braille block. Implementation read upstream `Packages/macOS/CmuxTerminalCore/Sources/CmuxTerminalCore/TitleChurn/TerminalTitleChurnFilter.swift` at `bd1288e5dc7c815e54a610e20bb36f21f9169dc2` (#10351), adding the missing asterisk/quadrant frames and preserving adjacent glyph runs. Do not adopt "strip every braille character."

Call the filter inside the existing main hop in `GHOSTTY_ACTION_SET_TITLE`, before `NotificationCenter.post`. Store its last admitted OSC title on the TerminalSurface instance and update that state immediately before posting; do not read workspace.tabTitles as the previous OSC value. That dictionary is downstream of the 30 Hz coalescer and metadata precedence. Concrete failure: applied title claude, then npm test and claude ◐ before the coalescer drains. Comparing with the stale claude drops the return-to-claude update and leaves npm test displayed. A declared title can likewise differ from the OSC stream. Per-TerminalSurface state also dies with the surface and needs no global UUID cache. A drop posts nothing, so the coalescer, metadata write, titlebar refresh and toolbar refresh do not run. No second queue and no observer filters.
