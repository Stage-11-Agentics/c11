C11-294 adds `ghostty_surface_try_read_text(surface, selection, result)` returning `GHOSTTY_TEXT_READ_OK`, `BUSY`, `INVALID_SELECTION` or `FAILED`. ## Shared bounded-read policy with C11-282

C11-282 (CLI owner) adopts C11-295's existing bounded-read/lifetime policy: one monotonic five-second worker/caller deadline; main-thread target/liveness revalidation and native read; independently copied bytes only across the worker boundary; exactly-once native-buffer release on main while the surface is live; abandonment checked before late capture and no late publication after timeout. Where the native try-read returns BUSY, return the typed busy error without spin/sleep on main. C11-282 owns its selection implementation and records any native acquisition/capture limitation that its actual API retains; this shared policy adds no new native export or snapshot mechanism.

Both tickets distinguish bounded caller wait (and try-lock acquisition where supported) from native formatting/allocation/copy on main, which the deadline cannot preempt. A post-read selection size clip does not bound native allocation or main-thread time. C11-282 measures its large-selection fixture against the registered budget and explicitly records remaining native-on-main work; worker JSON/encoding alone is not full off-main native selection. C11-295 continues to own screen/scrollback handling only.
