# C11-217: Move browser.* socket handlers off the main thread so a legitimate wait never stalls main-marshalled commands

Residual from C11-209 (PR #433, shipped in 0.65.1). C11-209 fixed the never-loaded WKWebView wedge (fail-fast in 0.14s), made download.wait resolve early, and capped timeout_ms at 120s. What it deliberately did NOT do: move browser.* out of v2MainSync into socketWorkerV2Methods, because those handlers are @MainActor-isolated (production stack: MainActor.assumeIsolated directly above v2BrowserWait). Measured consequence on the validated tagged build: on a LOADED page with an unmet 20s wait, 'c11 tree' stalled 10.0s while 'c11 ping' answered in 0.142s, i.e. every main-marshalled socket command (tree, read-screen, focus, send) still waits out any in-flight browser wait, now bounded at 120s instead of unbounded. Work: make the browser wait/eval family complete asynchronously (or run its await off-main with only the WebKit calls hopped to main), keep the C11-209 tests and harness (tools/await-wedge-repro) as the regression oracle, and re-run the positive-control probe: 'c11 tree' must answer in well under 1s during a 20s unmet browser wait on a loaded page. Read docs/c11-browser-await-main-wedge.md first.
