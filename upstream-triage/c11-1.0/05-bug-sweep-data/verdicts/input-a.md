## Top findings

Workspace creation still carries live Workspace objects and borrowed Ghostty configuration through initialization, then assigns the old tabs array back. PRs 2023/2133/2173/2178/2181/2204 address successive versions of this crash family. This deserves a value-only reimplementation because Atin frequently creates and closes surfaces. PR 1985 separately exposes incomplete restore cleanup. Neither finding establishes the cause of the July deadlock or fixes the [August teardown mailbox deadlock](/Users/atin/Projects/Stage11/code/c11/notes/2026-08-25-freeze-surface-deinit-deadlock.md).

Clipboard correctness is only partly covered by C11-21. PR 2847 removes a shortcut path that can request paste twice and leave only its first character. PR 3929 recovers richer Unicode when the producer supplied lossy plain text. Both shared paths can corrupt pasted prompts or commands. PR 2877's UTF-8 preference is already fixed; PR 3268's rich-first regression never reached c11.

PRs 4613 and 4676 directly matter at 10-40 agents. App deactivation still builds the full session snapshot on main, and v2 system.ping still waits for main-thread dispatch and reference refresh. These add work or delay observability during known problem 2's congestion. Moving heartbeat dispatch off-main does not repair the sidebar storms, metadata lock wait, or hover recursion. The v1 ping fast path is already separate.

Focus repair remains incomplete across creation and reparenting. PRs 2088/2511 preserve desired focus before Ghostty exists; 2354 prevents closed-runtime recreation and retries missing input surfaces; 2505 repairs a stranded first responder. These can explain apparent input freezes, inferred from matching paths. They do not prove a main-thread deadlock. c11 already has basic surface readiness and its own queued-submit handling, so adaptation is required.

Quit and close routing deserve small focused fixes. PR 2186 protects Warn Before Quit when termination originates in the app switcher. PR 4615 resolves close actions against the actual focused window instead of stale event or manager state. Both can terminate active agents.
