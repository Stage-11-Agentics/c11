**Evidence.** Base `0ff8887e5e`: `WorkspaceManager.restoreSessionSnapshot:5658–5755` unwires browser tracking and probes, builds replacements and assigns `workspaces = newTabs`, but never explicitly closes the old panels/remote connection or prunes background loads. **Small implementation.** Change `Sources/WorkspaceManager.swift:restoreSessionSnapshot` and a narrow Workspace retirement helper in `Sources/Workspace.swift`. Capture old objects, cancel their existing manager probes/tracking, stop their per-object mailbox dispatcher and remote connection, clear owning-manager links, and explicitly close panels. Perform ID-keyed cleanup before constructing/registering replacements with those same UUIDs. Keep the old workspace-array reference until the final existing `workspaces = newTabs` / selection publication; never publish an empty array between graphs. Retain current empty-snapshot fallback. After installation, prune background-load/sidebar selection IDs against the installed set. Do not route retirement through normal closeWorkspace (last-workspace guard, notification and selection policy differ).

Reuse `TerminalTab.close` → `TerminalSurface.teardownSurface`: it invalidates the runtime handle immediately and frees Ghostty on the next main-actor turn. Do not move free off main or add synchronous waits. Existing delayed resume callbacks look up panels on the old object and become no-ops when its panel map is empty; verify this with an externally retained old workspace. Audit only callbacks exercised by that fixture. If safe ordering requires wider lifecycle machinery, return the concrete finding to Orchestrator rather than expanding this slice. Do not delete logical notifications merely because a workspace object was replaced with the same ID.

Repeat with distinct IDs and the empty-snapshot fallback; verify selection and stale background-load pruning. These execute the restore path, not source patterns.
