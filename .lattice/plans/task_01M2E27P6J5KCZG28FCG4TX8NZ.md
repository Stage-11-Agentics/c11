# C11-226: Socket main-thread commands stall for 10s+ when the c11 window is fully occluded (App Nap)

Seen 2026-09-13 while validating C11-225 on a tagged Debug build whose window sat fully behind the production c11 window: `workspace.select`, `surface.send_text`, `surface.send_key` and `get-metadata` each timed out at the CLI's 10 s deadline (main_thread_timeout) while off-main reads (`tree`, `read-screen`) answered in <0.2 s. The hang log recorded `cause=runloop-idle active=0 visible=0` with the main thread parked in mach_msg inside the normal NSApplication run loop, one entry spanning 115 s. Nothing was blocked: macOS App Nap had put the occluded, non-active app to sleep, so dispatches to the main queue were serviced late. `defaults write <bundle-id> NSAppSleepDisabled -bool YES` and a relaunch made every command sub-second again.

Why it matters: c11 is an agent host. When the operator covers the c11 window with another app (or a tagged/staging build is launched behind production), every agent-driven main-thread socket command stalls or fails, and the socket layer reports it as a main-thread timeout, which reads like a hang bug. Production's own hang log already carries many `runloop-idle active=0 visible=1` entries; whether any are nap-induced is worth checking.

Fix options: (a) `LSAppNapIsDisabled` / `NSAppSleepDisabled` in Resources/Info.plist (blanket, simplest); (b) hold a `ProcessInfo.processInfo.beginActivity(.userInitiated, reason:)` assertion while at least one socket client is connected or a pty has produced output in the last N seconds, so an idle covered c11 can still nap; (c) both. Prefer (b) if the energy cost of (a) is a concern on Hyperion; otherwise (a). Add a runtime test through the socket: launch a QA build occluded, issue `workspace.select`, assert <1 s.

Also note for validators: the c11-computer-use / hotload skills should say that a tagged build launched behind production will nap and fail socket main-thread commands unless the window is visible or NSAppSleepDisabled is set on its bundle id.
