# C11-147: Mailbox/shell-integration: report_shell_state dropped — CMUX_TAB_ID is surface UUID, scope resolver expects workspace UUID

Discovered during C11-144 live validation. In a tagged Debug build, terminal surfaces export CMUX_TAB_ID == CMUX_PANEL_ID == CMUX_SURFACE_ID (the surface UUID), while CMUX_WORKSPACE_ID is the distinct workspace UUID. The shell integration sends 'report_shell_state <state> --tab=$CMUX_TAB_ID --panel=$CMUX_PANEL_ID', but TerminalController.explicitSocketScope interprets --tab as the WORKSPACE id, so tabManagerFor(tabId: <surface-uuid>) finds no tab and the report is silently dropped. Net: panelShellActivityStates never updates from the integration (0 surface.shellState events in the tagged debug log; only correctly-scoped manual socket reports landed). This degrades BOTH close-confirmation and C11-144's prompt-gated stdin flush (state stuck .unknown → everything buffers, push-flush never auto-fires; delivery falls to the recv --drain pull floor). C11-144 ships safe regardless (unknown → buffer is conservative) but its push-flush path can't work automatically until this is fixed.

Repro (tagged build): open a terminal, run 'echo $CMUX_TAB_ID $CMUX_WORKSPACE_ID' — TAB_ID matches SURFACE_ID, not WORKSPACE_ID. grep /tmp/c11-debug-<tag>.log for 'surface.shellState' → none from the integration.

Fix options: (a) export CMUX_TAB_ID as the workspace UUID (what the resolver needs), or (b) relax explicitSocketScope / reportShellState to resolve a panel by surface UUID across workspaces. Confirm on prod first (the c11 skill documents a DIFFERENT historical value, 'TAB_ID == workspace UUID', so the export may have drifted). Deliverable: integration shell-state reports land on the correct panel (surface.shellState events appear), verified by a runtime test or live repro.
