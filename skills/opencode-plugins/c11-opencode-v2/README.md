# c11 OpenCode 2 TUI plugin

This local plugin is loaded per OpenCode 2.0.25 TUI by `Resources/bin/opencode`. It uses the TUI's own current route and loaded session record to capture the exact displayed root. Capture is sent directly from the TUI process over c11's Unix socket; c11 requires that socket peer PID to match the PID recorded by the wrapper claim. A tool subprocess inheriting the shared server's `C11_PANEL_ID` cannot claim a displayed route or register the native OpenCode mailbox stream. The plugin does not load into the shared server and does not read or write OpenCode tenant configuration.

Before launching an explicit `-s`/`--session` resume, the wrapper creates an expiry-bounded c11 reservation. The plugin captures only after `data.session.get(id)` returns the displayed row and that row has no parent. Capture is atomic in c11; another panel's exact ID or resume reservation rejects a conflict. The plugin keeps a provisional mailbox route while hydration/capture is pending so mail is not typed into an unverified route. A conflict rejects with `session_conflict`; c11 holds the affected envelopes until a new route is captured.

Native delivery sends the fixed c11 invitation through `client.session.promptAsync`, then waits for matching user-message and text-part events from that exact session. Invocation alone does not acknowledge. Busy/retry, permission/question, child, unresolved, route-change, and ownership-conflict states cannot open a different session. The plugin never reads or edits the composer.

The v2 adapter currently provides exact root capture and native mailbox confirmation. A route conflict remains held out of typed delivery even when native stream registration fails, and the same route is retried until ownership clears. It does not report lifecycle/status, prompt-cache, or permission-notification telemetry. v1 keeps its existing server plugin and TUI integration; unknown OpenCode versions receive no plugin injection and retain typed fallback. Generic c11 commands invoked by shared-server tool subprocesses may still use inherited caller-panel environment; this adapter does not use them for identity or mailbox ownership. See [the mailbox guide](../../../docs/c11-mailbox-guide.md#opencode-plugin-compatibility) for the feature matrix and residual.
