# C11-178: Launch stats rail: agent-launches.jsonl, rolled-up aggregate, recordLaunch sink

Design: docs/agent-config-primitive-design.md §2.4, §4.1, §4.4, §8.6. One recordLaunch(resolved{harness,model,effort,provider,system_prompt_mode,config_id?}, source ∈ a-button|launch-agent|socket|blueprint|fader) sink that (a) updates the persisted recent observation (source-ranked: launch ≥ sessionHook ≥ scrape — a stale scrape never clobbers a newer launch), (b) appends one line to agent-launches.jsonl, (c) bumps the agent-launch-stats.json aggregate (by_model/by_harness/by_provider, count, last_ts). Windowed queries (today/30d/all) scan the jsonl; aggregate answers all-time O(1). Never stores prompt/command text. Provider derived per §1.2 (fixed harness map, or model-id prefix for router harnesses). Wire rail-1 call sites: launchAgentSurface (A button), AgentLaunchPlanner/agent.launch, blueprint spawn. Files at state root, atomic writes, app-down CLI-readable. AC: append+aggregate consistency; windowing math; source-rank tiebreak; derived provider incl. prefix parse. Pure logic — c11-logic test loop.
