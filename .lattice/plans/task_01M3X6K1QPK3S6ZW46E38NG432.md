### Producer policy and ownership detail

The eighteen-site summary is not a complete count at this base. Inventory every existing `Surface.zig` forever producer by role: inspector activation/deactivation, config/font-grid changes, search callbacks (including quit), search request/navigation, focus/visibility and debug crash. Also cover the reader's three queues and `Exec.childExited/termiosTimer` app publications. `renderer/generic.zig:frameCompleted` has a forever health publication before releasing the frame semaphore; that must honor the same cancellation so the renderer-first join can finish. This is the named B010 producer-policy work, not extra renderer hardening.

- Live worker publication keeps backpressure and preserves messages. Cancellation applies to that dying producer/surface, never globally closes the shared app queue or drops another live surface's messages.
- Main cannot make progress on its own future cancellation while parked. Focus/visibility use the atomic slots. Other main-origin ordered messages use a queue-owned FIFO spill on the rare full-queue path, drained by the existing consumer with the same bounded count and wake rules. Implement a narrowly scoped non-waiting enqueue in `blocking_queue.zig`, used by `Surface` renderer/search publishers and the main-origin termio send path. Once spill exists, later messages cannot leapfrog it into newly freed ring slots. No new worker, timer or app-level render loop. Allocation failure is explicit at fallible callers, with owned payload cleanup and an error diagnostic at existing void API boundaries; it is never reported as successful enqueue.
- Add/centralize typed message disposal only for the changed enqueue/cancel paths in `apprt/surface.zig`, `termio/message.zig`, renderer messages and search messages. The sender owns a rejected message; the consumer owns an accepted message. Close drains/disposes unconsumed payloads after worker joins. Tests use an allocator to verify no double free/leak. Cancellation and queue storage outlive all workers and renderer completions using them.
- Search quit on a live surface must still clear renderer highlights and surface totals. Perform that reset from the owning surface after joining; cancellation of the search worker must not lose the final reset.
- Keep normal queue capacity 64. A larger queue is unnecessary to prove this repair and would hide the saturation fixture; the final ticket requires abortability, not the superseded mitigation alone.

### Child keep rule and deadlines

Our assumption follows the final upstream safety correction: terminate the still-owned direct child/process group and a distinct foreground group freshly attributed through the retained PTY; never signal c11's own group, invalid IDs, an already-reaped child's cached numeric group, or detached/disowned processes no longer attributable to that PTY. Do not traverse and kill arbitrary descendants by ancestry alone.

Use a 12 s HUP grace for a cooperative handler, 250 ms TERM grace for a Darwin leader verified to ignore HUP, then a 3 s KILL/reap budget with 10 ms polling. Validate complete Darwin process records before trusting ignored-signal masks; unknown records take the graceful path. Bound pre-setsid group discovery inside the same deadline. Handle ESRCH/ECHILD as termination/reaping outcomes, and return/log timeout rather than looping forever. Keep direct child and foreground-group state separate: reaping the leader does not prove an attributable foreground job has exited. Inject shorter durations in tests; production close ceiling is the configured phase budget plus scheduler tolerance. No session hook/config changes.
