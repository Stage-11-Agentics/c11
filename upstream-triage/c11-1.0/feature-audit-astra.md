# 1. Verdict in five lines

Needs you: nothing for this audit. My recommendation is a reliability and attention-navigation 1.0.
Ship safe targeting, predictable restore, a read-only Feed, and a small set of useful CLI additions.
Defer the authoritative lifecycle journal and native remote-session stack to 1.x.
Cut automatic menu answering from this design. A screen check cannot make a later keypress safe.
Spend the last two weeks on integrated builds, recovery, resource budgets, and Atin's sign-off.

# 4. Red team

## Against the event journal

The strongest case is that it solves an attractive abstraction before it solves the observed information problem. A durable record cannot invent a missing permission event. It cannot tell whether an old blocked prompt still exists after its PTY died. It cannot turn delivery order into causal order. It can make an incorrect state more persistent and more convincing.

The proposed late-event example is decisive. `Stop` arrives first and receives sequence 10. An earlier asynchronous `PreToolUse` arrives later and receives sequence 11. A newest-sequence fold restores “working.” Appending successfully did not fix the incident. The upstream reducer actually checks both sequence and `occurredAtMs`, with a special exemption for state assertions. It does not rely on the sequence rule alone. Cross-host clocks and events without trustworthy source time complicate even that approach. This is an inference from U:`Packages/macOS/CmuxAgentJournal/Sources/CmuxAgentJournal/AgentLifecycleReducer.swift:62-81` and C:`Resources/bin/claude:205-207`.

The transcript fallback is also overstated. The current parser records prompt, agent output and tool results. It does not represent blocked, completed and interrupted as separate events. Grok reads a summary; Kimi and Copilot are unsupported. A poll exceeding 4 MiB skips the beginning of the backlog. Those are sensible limits for clocks, but inadequate as an exhaustive journal producer. Sources: C:`Sources/AgentModelDetection.swift:88-92,118-119,132-176,270-280,390-427`.

The store proposal hides a second delivery system. A timed-out hook might already have committed, then spool the same event. The drain needs stable event IDs, ownership checks, retention, partial-line recovery and deduplication. “A few dozen lines” is not an estimate of that contract (`01-event-journal.md:247-255`). Upstream uses a transactional uniqueness check and rejects same-ID/different-content retries, U:`Packages/macOS/CmuxAgentJournal/Sources/CmuxAgentJournal/AgentJournalStore.swift:78-108`. Time retention also needs a retained current-state baseline: deleting a 15-day-old still-open ask must not silently delete current state. These are concrete inference cases, not a demand for distributed consensus.

The C11-188 guardrail cannot simply ban epochs, fences or transactions while requiring the properties those mechanisms were introduced to protect. The AAR says to bound the promise and use empirical evidence. It does not say legitimate ownership and crash cases cease to matter. C:`docs/aar-c11-188-attention-loop.md:39-68,94-99`.

**Does the case win? Yes, against the proposed 1.0 journal. No, against ever having one.** First ship the small state repair and a snapshot API. Capture real failures and source coverage. In 1.x, introduce a bounded journal with a declared ordering model and a single authoritative owner. If durable dedupe, queries and compaction are requirements, start from the small SQLite storage core rather than rebuilding a database in NDJSON. Keep an NDJSON export for inspection. Do not import auto-resume, decision policy or messaging merely because they share the upstream package.

## Against agents on remote hosts

The strongest case is not that Atin has no need. It is that the plan confuses three products: a durable remote terminal, trusted telemetry from that terminal, and migration/federation of agent sessions. Only the first is required to close Hyperion's lid. c11 already has a detached tmux launcher whose stated purpose is surviving SSH detach, C:`Resources/bin/c11-spawn-agent:1-13,125-157`.

The native proposal deliberately avoids cmux's current remote architecture, ports parts of its older Go stack, replaces that stack's transport, moves c11's ownership boundary from workspace to tab, and then adds a data mover that understands provider storage. That is new integration work with borrowed components. The Go PTY state alone includes bounded queues, attachment tokens, input sequences, startup claims and teardown coordination, U:`daemon/remote/cmd/cmuxd-remote/ws_pty.go:96-205,960-1040,1583-1656`. It is not just spawning a PTY that ignores SIGHUP.

The security boundary is easy to describe incorrectly. An SSH-authenticated host is not a trusted local agent. A slot ID supplied by that host is not authority. A 0600 socket with a UID check separates Unix users, not hostile processes sharing that UID. A remote host holding multiple slots can generally speak for the slots it owns unless there is a stronger isolation model. Therefore bind capabilities on the Mac to the carrier and admitted slots, validate every field, constrain attribution, bound rates, and deny all cross-tab input, including mailbox delivery. U:`Packages/macOS/CmuxRemoteWorkspace/Sources/CmuxRemoteWorkspace/Relay/RemoteRelayCommandPolicy.swift:18-40,78-119,124-164`; C:`Sources/Mailbox/StdinMailboxHandler.swift:103-115`.

Finally, a reconnect timeout does not prove a process is dead. “If holder gone, type resume” needs a positive absence result or an explicit operator action. Moving stopped sessions needs cooperation from both hosts and every potential writer; a local conversation-store lock cannot freeze someone starting the CLI directly. The existing upstream mover writes code before copying session data and merges memory in both directions. A rollback ref restores neither a concurrent external edit nor a partially merged memory tree. U:`Packages/macOS/CMUXAgentLaunch/Sources/CMUXAgentLaunch/AgentMove/AgentSessionMover.swift:64-68,103-122,145-166`.

**Does the case win? Yes, against full remote citizenship in six weeks. No, against the long-term investment.** Native remote execution may be the highest-value 1.x feature for Atin. Build a workspace-scoped holder and attach/reconnect path first. Then add minimal report-only telemetry. Per-tab hosts, movement and federation follow separately. Meanwhile validate a tmux recipe and continue using existing Atlas workflows. Public users without remote hosts should receive a good 1.0 without paying its resource or support costs.

11. **Phone does not depend on full remote tabs or a journal.** Atlas can originate pushes for its own flags today. Use events to trigger a snapshot refresh, since the file stream is explicitly lossy. A sleeping Hyperion cannot originate a timely notification for a remote agent through a disconnected local bridge. C:`Sources/Events/EventLog.swift:70-89`; C:`Sources/AttentionModel.swift:398-429`.
