## View

Replace the popover root with `FeedQuickView` in the same file (or `Sources/Feed/FeedQuickView.swift` if the accessory file should only keep the AppKit seam). `popoverDidClose` still nils the content controller (`:999`).

The view takes an `Equatable` snapshot: ordered ask/flag rows, ordered `turn_end` rows, the jump sequence `navigationCandidates`, and a one-line status. It does not read `TerminalNotificationStore`, `workspaceManager`, or `TabAttentionIndex` in `body`. The controller publishes the snapshot from C11-264's projector and C11-265's jump sequence when those change, and only while the popover is shown.

`navigationCandidates` is assigned from C11-265's three-class sequence (flags, blocked asks, eligible completions and legacy notices). It is not derived by subtracting the hidden segment. A legacy notice with no journal row is not given a new popover row. It stays in `navigationCandidates`.

Fixed geometry, all states, including empty and loading:

- Popover content `520×420`. Set `preferredContentSize` once. Empty and populated use the same size.
- Header row height 44. Title `feed.quick.title` = "Feed".
- Filter control width 200, height 28. Two segments, each `frame(width: 100, height: 28)`: `feed.quick.filter.asks` = "Asks", `feed.quick.filter.turns` = "Turns". `lineLimit(1)`, tail truncation. The control does not grow for locale strings.
- Status line height 16, always present. Empty string still takes the line.
- List region fills the rest. Each row `frame(height: 64)`.
- Hint bar height 28, always the same string.

Row contents, each in a reserved slot so a missing value does not remove the slot (truncate visible text; expose bounded detail via accessible description/help without resizing):

- Kind glyph, 16×16.
- Title, one line, tail truncation. Workspace or tab name.
- Age, 48pt, monospaced digit, tabular. Missing age is `feed.quick.age.missing` = "—".
- Source/confidence/confirmation, one line in a reserved slot, using the journal source and existing `journal.evidence.unconfirmed` key. Null is the existing missing marker; do not fabricate hook confidence. Source labels and rank formatting use the localized keys below.
- Prompt, one line. Missing prompt is `feed.quick.prompt.missing` = "—". Do not use `lineLimit(3)`.
- A flag and an ask on one tab is one row (C11-264), shown in Asks.

Clocks update from the snapshot only. Do not add a per-second timer on a terminal view. A one-minute tick may live on the popover controller while the popover is shown; it must not invalidate `WorkspaceRowView` or call `forceRefresh`.

Theme: existing semantic colors (`windowBackgroundColor`, `controlBackgroundColor`, the current accent). No new palette. Reduce Motion: pass `animated: false` into `toggleNotificationsPopover` when `NSWorkspace.shared.accessibilityDisplayShouldReduceMotion` is true. No other motion.

## Filters and selection

Pure type `FeedQuickViewSelection` in `Sources/Feed/FeedQuickViewSelection.swift`.

- Asks shows `AttentionOrder.ordered` (flags, then oldest open asks). `turn_end` rows are not in that visible list.
- Turns shows the `turn_end` rows from `feed list --scope all`, oldest first.
- Either segment only chooses the rendered rows. Switching segments does not remove, reorder, or nil `navigationCandidates`.
- The popover does not call `jumpToLatestUnread` with the visible rows. The shortcut and the menu item keep walking the full sequence while the popover is filtered or closed.
- Header counts are the two visible list counts, in a fixed-width text slot. A `turn_end` is not in the Asks count. Those counts are not `unreadCount` and are not the jump sequence.
- Selection key is the tab UUID, not the index.
- Insertions and age changes keep the selected UUID.
- If the selected UUID disappears from the visible list, select the row that now sits at the old index, or the last row if the index is past the end. If the visible list is empty, selection is nil. This move does not open the tab and does not edit `navigationCandidates`.
- Switching filters keeps the UUID when it exists in the new visible list; otherwise selects the first visible row and does not open it. Filter clicks do not open.

## Keys

While the popover is shown, a local monitor (installed in `toggleNotificationsPopover`, removed in `popoverDidClose` and teardown) handles only events for its owning window/popover. Pass through keys in another c11 window and keys with unrelated modifiers. This prevents one Feed from swallowing another terminal's typing. It handles:

- Up / Down: move the selection inside the visible list.
- Return: open the selected visible tab through C11-264's `feed.open` resolver. Then close the popover. Do not restore the previous responder; the open path focuses that tab.
- Escape, and ⌘I while open: close and restore the first responder captured before show, if it still exists.

Return is not a default button. The view has no Approve, Reply, Clear All, or Jump button. Arrow keys do not change the filter. The monitor is absent when the popover is closed, so terminal typing is untouched.

Before show, save the originating window and a weak first-responder reference. Restore only if that responder still belongs to that same live window; do not redirect focus to another window if it disappeared. Add a behavioral monitor-lifecycle case: open/close/reopen installs one monitor, and an arrow/Return in another window is delivered to its original target. Before show, save `NSApp.keyWindow?.firstResponder`. A missing panel returns C11-264's `unavailable`. The status line then shows `feed.quick.unavailable` = "That tab is unavailable" and the popover stays open. The line is the same 16pt slot.
