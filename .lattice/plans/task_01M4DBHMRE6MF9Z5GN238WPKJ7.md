## Architecture

- Add a shared, bounded `MarkdownCorpusIndex` service, keyed by canonical corpus root. In PR #626, N1's private `MarkdownNavigationPolicy.documentRoot(for:)` lives in `Sources/MarkdownAssetPolicy.swift`: it walks upward from the resolved source file to the nearest `.git` marker, then falls back to the source file's containing directory. Promote that rule through a small shared helper and use it for indexing and navigation so the roots cannot drift; keep symlink resolution consistent with N1. Do discovery, reads, parsing, and updates on a utility actor/queue. Keep only eligible Markdown paths, headings, local-link targets, and ticket references in the bounded snapshot; never scan synchronously from a keystroke or renderer callback.
- Exclude `.git`, `node_modules`, `DerivedData`, `build/`, `dist/`, and `.build`; do not follow symlinks outside the canonical root. Bound file count, per-file bytes, total indexed bytes, result count, and result text. Proposed starting caps: 5,000 Markdown files, 1 MiB per file, 64 MiB total source. Keep the limits as named constants and cover each in behavioral tests.
- Watch the corpus with filesystem events. Coalesce bursts on the worker queue, re-index only changed/added/deleted files, cancel the watcher when the root has no consumers, and publish immutable snapshots. A plain directory uses the same index rules without requiring Git metadata.
- Feed the renderer a small corpus snapshot through the existing native/page bridge. The page owns the ⌘K palette and backlink presentation; native owns discovery, file reads, the `.lattice` board lookup, and navigation. No new page file or network access. Palette rows cover Markdown files and their headings. N1 now exposes `linkIndex()` for the current document and `inspectMarkdowns(markdowns)` for heading inspection of at most 128 supplied documents; keep corpus indexing bounded and off the renderer callback path rather than turning either bridge call into a per-keystroke corpus scan. N1 also owns a relative-link `linkPeek` overlay; ticket cards need their own board-backed data path while coordinating stale-request cancellation and overlay dismissal with that existing preview.
- Palette and backlink selection navigate only through N1's API: `@MainActor @discardableResult func MarkdownPanel.navigate(to fileURL: URL, fragment: String?, origin: MarkdownNavigationOrigin) async -> MarkdownNavigationOutcome`, using `.palette` and `.backlink` respectively. Call it on the main actor and await the result. N1 captures the current reading position, validates and reads the target off-main, records per-panel history (bounded to 100 entries), and does not change panel/workspace selection. Outcomes are `.navigated`, `.unchanged`, `.invalidTarget`, `.notFound`, `.notReadable`, `.outsideScope`, `.superseded`, and `.panelClosed`. `.navigated` confirms the file navigation was accepted; fragment resolution occurs in the page after rendering, where a missing heading opens N1's closest-heading suggestions, so do not treat that outcome as proof the fragment exists. Handle rejected outcomes without any alternate navigation path; do not add a shim or recreate N1 history/peek. Develop the ticket branch from `origin/main` without N1 commits. For local integration, make a disposable scratch branch from this ticket branch and merge `origin/md-viewer/C11-362-in-panel-nav` at its current reviewed head (`6148809111479eb652470591e172d5321f0fa5eb`, which contains the approved API commit `ca740921b7bed9272cc11d68c8903710ca121ed4`). This exercises the API with N1's actual renderer and toolbar additions. Never merge/cherry-pick N1 into `md-viewer/C11-363-corpus`. Once N1 merges, rebase the ticket branch onto the resulting `origin/main` and resolve shared files against the merged implementation.
- Parse local Markdown links and their source section to build backlinks for both the current document and heading. Ticket IDs link only when the corpus root contains `.lattice/`; resolve title/status read-only, render the hover card, and leave the text plain when no board exists. No board writes or hosted calls. Keep palette/backlink actions on the direct `.palette` / `.backlink` API path; do not synthesize page link clicks or call N1's document-link/new-panel routing.
- Extend the existing Markdown agent-command route with `c11 markdown backlinks --panel <p> --json`, returning the same bounded index results without changing focus. Follow the C11-361 explicit `--panel`, socket worker, capability, and JSON conventions after that parent merges.

## Cut line, threading, localization, persistence

- In scope: one open file's Git repository (or containing directory), bounded local Markdown indexing, palette, document/section backlinks, and local `.lattice` ticket title/status cards.
- Out of scope: editing, diff/change tracking, remote search, indexing across workspaces, a general Lattice client, reimplementing N1 history or relative-link peek, and Vimium-style link hints. Follow the binding design doc over the round-1 prototype.
- File discovery, file reads, parsing, and filesystem updates stay off-main. Renderer input and returned results are bounded. Only the minimal WebKit call/navigation hop may touch the main actor; do not use `DispatchQueue.main.sync` for watcher or query traffic. Keystrokes only filter the current immutable snapshot.
- N1 adds the persisted `markdown.links.openInNewPanel` toolbar preference for ordinary document links. C11-363 adds no preference or durable panel state: its cache is ephemeral and reconstructible, and palette/backlink selection always stays in the current panel regardless of that preference. Any new page-visible strings go through the native localized bridge map and all six locales in the PR. No tenant settings, installs, or board writes.
