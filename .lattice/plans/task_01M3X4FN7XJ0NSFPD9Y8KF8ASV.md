# C11-282: Terminal selection read with bounded acquisition and caller wait

## Incident and verified base
Base `0ff8887e5e965400b01645ef40b85fd0b2605cf2`. Backlog C4: an agent cannot read the word the operator selected. No `read-selection` CLI or `tab.read_selection` method exists. `GhosttyTerminalView.swift:5030-5031,5267-5271` calls the blocking `ghostty_surface_read_selection` and releases a successful allocation on main. `embedded.zig:1655-1667` takes the renderer mutex, resolves the active user selection and formats under that lock. `ghostty_selection_s` is an explicit rectangle/range, not the current selection; the planned try_read_text API cannot substitute for a current-selection read.

Audit finding 9 supersedes the previous unlimited semaphore wait and full-buffer copy claim. The 1 MiB response clip is not a native allocation or main-time bound. This ticket implements worker dispatch and Swift post-processing off main; native formatting and bounded-byte copy remain on main.
