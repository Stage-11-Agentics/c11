# c11 vs cmux, 2026-10-08

Prep for meeting cmux's founder tonight. Every number comes from a command run today against `origin/main` (c11, `7b13e8c6b4`, 2026-10-08) and `upstream/main` (cmux, `ed6ee7d86e`, 2026-10-08), from the two CHANGELOGs, or from `gh`. Fork point: `53910919`, 2026-03-18. **Inferred** marks anything not read directly.

## 1. Needs Atin: nothing. Headline

- **Same root, opposite bets.** cmux is turning into a platform company: Cloud VMs (now on for everyone in 0.65.0), an iPhone app, a headless Rust session server, team accounts, and a paid Pro tier at $480/yr (#18162). c11 stays a local, account-free room for one operator running a fleet of agents.
- **Scale gap is roughly 9x.** By program code, cmux is 3.45M lines and c11 is 384k. At the fork both were 186k. c11 doubled; cmux grew 18.6x. Only about a quarter of cmux's growth is in the core macOS app. A third is new subsystems (TUI server, iOS, cloud, agent chat, simulator) and almost 40% is tests.
- **Velocity gap.** Since the fork: c11 has 910 non-merge commits, 875 of them by Atin. cmux has 15,746 commits from 206 author names, and has merged 569 PRs since 2026-10-05 alone.
- **The real doctrinal split is agent hooks.** `cmux hooks setup` writes hooks into 19 agents' own config directories (`docs/agent-hooks.md`). c11 never writes tenant config. It passes hooks per process at launch through 7 PATH wrappers, and its PHILOSOPHY says "Observe from outside, never hook into agents."
- **c11 1.0 is a harvest of cmux ideas, rebuilt c11's way, not merged code.** Workspace groups, Feed, lifecycle journal, strict socket keys, `--command` on splits, `read-selection`, `resize-window`, `guide`/`rpc`/`capabilities`, focus history and browser profiles all trace to the 2026-10-01 cmux landscape. No app commit cherry-picks a cmux PR. The Ghostty bump does carry fixes authored by cmux engineers.
- **The two projects are converging in the same weeks.** Both shipped strict socket keys, agents that can't steal the visible workspace, a second launch that yields to the running instance, holding back a poorer session save, and journal-backed agent status. Most landed within days of each other.
- **Licenses diverged after the fork.** c11 carries AGPL-3.0 from the 2026-03-18 fork. cmux went GPL-3.0-or-later (#2364, 2026-03-30), then put its server code (`web/`, several `workers/`, relays) under BUSL-1.1 (#15206, 2026-09-28).
- **c11's distinct contributions are operator-pair primitives.** These are per-panel metadata and declared agents, the mailbox, flags, workspace roots, the prompt-cache cold mark, guarded sends, and skills bundled with the app. Markdown panels are not c11-only: cmux shipped them before the fork (0.62.0, #883).

## 7. Philosophy divergence

**cmux.** The README still says: "cmux is a primitive, not a solution… cmux doesn't force you into an opinionated way to use coding agents," and "Give a million developers composable primitives and they'll collectively find the most efficient workflows." In practice it now ships many opinionated solutions: hook installers for 19 agents, Cloud, CodeRouter, an iOS app, Vault and Automations. Its business model is attached as well: Founders Edition ("early access to… cmux AI, the iOS app, and Cloud VMs") and BUSL-licensed servers. It is a broad-audience product: 20 locales, and a tagline of "vertical tabs and notifications for AI coding agents."

**c11.** PHILOSOPHY.md says c11 "is host and primitive, not an intelligence layer." It also says: "Observe from outside, never hook into agents… The moment an agent has to be modified to work well in c11, c11 has already lost." The stated target is narrow: "the compound actor… often orchestrating extensive terminal-based LLM coding agents in parallel… Density over handholding." It is "local-first, file-based, and network-optional." The README pitch is "Agent-native Terminal Multiplexing for 10,000x hyperengineers." The intelligence lives upstairs, in Lattice and the Stage 11 stack.

## 8. Talking points for tonight

1. **"We forked on March 18 and took the opposite fork in the road."** cmux became a platform: Cloud, iOS, a TUI server, Pro. c11 stayed a local room for one operator and 30-plus agents. Both readings of "primitive" are legitimate.
2. **Ask how they run about 100 PRs a day with 200 authors.** cmux has merge-gate tooling (`gh-merge-green`, a cmux-next CI lane) and a single author with 1,677 commits. c11 runs one operator plus an agent fleet through Lattice, with builds on a Mac Studio. Compare notes on agent-authored PR quality.
3. **Hooks are the honest disagreement.** cmux writes into `~/.codex` and other agent configs; c11 refuses and passes per-process hooks at launch. Ask how they handle consent and rollback when `hooks setup` rewrites someone's config.
4. **Credit runs both ways.** c11 1.0's Ghostty bump carries fixes from Austin and Aziz. c11's C11-294 Ghostty work (abortable teardown, PTY backpressure) and its fleet-scale hang fixes may interest them. Inferred, with a caveat: the license direction matters. c11 can take GPL-3.0 code into its AGPL work under GPLv3 §13. Code going back to cmux would need Atin to offer it under GPL. Not legal advice.
5. **We keep landing the same fixes in the same week.** Strict socket keys, background-only agent opens, single-instance relaunch, held-back saves, journal status. A shared bug oracle, even informal, would save both sides work.

### Three c11 ideas their founder might find interesting

1. **The prompt-cache cold mark (#598).** The UI shows which idle agents will pay to re-read their context on the next message: exact for Claude Code, estimated for Codex and Grok. It is cost visibility at the panel level, which fits cmux's CodeRouter and usage interests.
2. **Guarded sends (#565) and verify-then-type Feed answers.** `send` refuses to type into a draft the operator has started or into a Claude chooser, and `feed answer` re-reads the screen before typing. This makes cross-agent automation safe without a hook decision bridge.
3. **The mailbox delivered at turn boundaries (#491 to #494, #625).** Mail to an idle agent becomes a new turn; a busy agent gets it at its next turn end; a panel where the operator is typing is left alone. Compare with cmux's new `agent message` inbox, which tackles the same problem.
