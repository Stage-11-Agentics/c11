# c11 OpenCode 2 TUI plugin

This local plugin is loaded per OpenCode 2.0.25 TUI by `Resources/bin/opencode`. That exact version pin is deliberate because the plugin calls in-process TUI APIs; advance it only after rechecking those APIs, passing this plugin suite, and repeating the two-client guest proof. Until then, unknown 2.x versions keep baseline lifecycle tracking. If the Python cache helper cannot run, the wrapper uses a bounded `/usr/bin/perl` version probe so OpenCode 1 keeps its existing plugins. Both probes terminate their process groups when they time out, including descendants holding stdout open; if neither probe can verify a version, it warns and disables version-specific integration. It uses the TUI's own current route and loaded session record to capture the exact displayed root. Capture is sent directly from the TUI process over c11's Unix socket; c11 verifies that the wrapper's claimed TUI PID is the foreground process-group leader for that terminal and that the socket peer is its descendant. Each displayed-route write carries a per-TUI generation, so c11 rejects delayed writes from an older route. The authenticated wrapper claim records the TUI process start time plus its `HOME`, `XDG_DATA_HOME`, and `OPENCODE_DB` for crash recovery; an exited or reused PID cannot keep owning a session. Explicit empty and in-memory database overrides remain unverifiable and never fall back to another store. The wrapper retries startup `not_ready` responses at most twice; if the claim is still unacknowledged, the loaded plugin retries it at an increasing rate capped at five seconds for the TUI's lifetime, before capturing any route. The wrapper claims the TUI before composing CLI plugin config; invalid or unreadable config can therefore leave an unbound placeholder, and expiry of an explicit resume reservation does not remove it. Typed delivery remains fail-closed until the exact root binds or the panel closes. On its next 100 ms route poll, the plugin retires the old stream and retries the unbind write until c11 accepts it. When native mail is enabled and a new route exists, a provisional stream rejects delivery until the new root binds; no new root is captured before the unbind is accepted. c11's typed gate closes when a verified claim or route change begins and reopens only after the current generation binds its exact root. A tool subprocess inheriting the shared server's `C11_PANEL_ID` cannot claim a displayed route or register the native OpenCode mailbox stream. Generic conversation pushes cannot forge claim metadata or replace an authenticated v2 route. A restored PID marker is not live authentication; the TUI must make a fresh claim before it can capture. The plugin does not load into the shared server and does not read or write OpenCode tenant configuration.

Before launching an explicit `-s`/`--session` resume, the wrapper creates a 120-second c11 reservation (the socket caps reservations at five minutes). The plugin captures only after `data.session.get(id)` returns the displayed row and that row has no parent. Capture is atomic in c11; another panel's exact ID or unexpired resume reservation rejects a conflict. When the UI route changes, the plugin first marks the old exact binding unbound; child and unhydrated routes stay placeholders, so typed fallback waits for a verified root. A conflict rejects with `session_conflict`; c11 holds the affected envelopes until a new route is captured.

Native delivery sends the fixed c11 invitation through the OpenCode 2 `client.session.prompt` API. It acknowledges only when the returned durable inbox item has the generated message ID, the exact bound session ID, the user item type, and the fixed invitation text. Busy/retry, permission/form, child, unresolved, route-change, and ownership-conflict states cannot open a different session. A busy rejection stays buffered and uses a named `not_ready` failure; when the displayed session becomes ready, the plugin replaces its native registration so c11 can retry the same invitation. The final typed fallback gate also rereads OpenCode identity immediately before any terminal input. The plugin never reads or edits the composer.

The v2 adapter provides exact root capture, lifecycle reporting, and native mailbox confirmation. For the currently bound displayed root, it reports `working` on `session.execution.started` or a `running` status, and `idle` on success, failure, non-shutdown interruption, or an `idle` status. The route monitor reconciles both status directions, so a newly bound idle root clears the previous root's working state, while child, home, unresolved, and shutdown routes do not synthesize an idle edge. Lifecycle CLI calls are serialized, acknowledged only after a successful exit, and retried after a short backoff on failure; each call has a 750 ms timeout. No shared-server event or child process supplies panel identity. `C11_OPENCODE_NATIVE_MAIL_DISABLED=1` disables only the native stream; exact root capture and lifecycle reporting remain, so typed fallback is safe for a bound root and held for a child, pending or conflicting route. A route conflict remains held out of typed delivery even when native stream registration fails, and the same route is retried until ownership clears. Prompt-cache and permission-notification telemetry remain unavailable in v2. v1 keeps its existing server plugin and TUI integration; unknown OpenCode versions receive no plugin injection and retain c11's baseline foreground lifecycle and idle reporting for typed fallback. Generic c11 commands invoked by shared-server tool subprocesses may still use inherited caller-panel environment; this adapter does not use them for identity or mailbox ownership. See [the mailbox guide](../../../docs/c11-mailbox-guide.md#opencode-plugin-compatibility) for the feature matrix and residual.
