Machines whose terminals c11 can show.

How c11 trusts a linked machine

What linking grants

Linking gives c11 a shell on the machine as the account you link with. c11 uses it to install hc, start it and open terminals there.

Same account, same trust

A c11 terminal on a linked machine is your own login shell. It has the same files, keys and permissions you have when you sign in there yourself.

No per-program check in hc

hc accepts connections from programs running as your account on that machine. It does not check which program is asking, so any program running as you can read and type into the c11 terminals there.

Shards separate failure, not people

hc splits terminals into shards so that one stalled group does not take down the others. Shards are about failure, not trust: every shard runs as you.

What stays on disk

hc is installed under your home folder, and its folders are readable only by you. c11 keeps the machine's host name and the hash of the hc it expects. It stores no passwords.

What c11 adds

Before it runs hc, c11 checks the file's hash against the one it expects. It keeps hc's folders private to your account and records every cross-machine action in its audit log.

Read the audit log

Run c11 machine audit to list every cross-machine action c11 has taken, with the time, the machine and the action.
