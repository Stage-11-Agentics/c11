# c11 2.0: prep plan

**Status: done, kept as history.** 2.0 was published on 2026-11-18 (one import commit, public PR
#936) and released as 2.0.0 to 2.0.2; the private development repo retired on 2026-11-28, and c11 is
developed on public `main` (`C11.md`). The rest of this file is the plan as written during prep.

Atin decided on Fri 2026-11-13, about 1:40 PM, that c11h becomes c11 2.0, stays open source, and
goes to GitHub publicly only on his go (`C11.md`, Decisions 1 to 3).

## What 2.0 is

c11h's code ships as c11 2.0 from the public `Stage-11-Agentics/c11` repo, under c11's identity:
the app name c11, bundle `com.stage11.c11`, the `c11` CLI, `C11_*` variables, and c11's Sparkle
feed and Homebrew cask. That way c11's existing users update into it. The c11h name, bundle and
repo retire, and the old c11h names keep working as hidden aliases wherever that costs nothing.
A later rename (11mux) stays possible.

## Measured (Fri 2026-11-13, 1:44 PM)

- **Line.** c11h is 765 commits ahead of c11's `main`, and lacks one c11 commit. c11 is already its
  ancestor, so c11's `main` can move to c11h's tip with no merge of two lines.
- **Rename surface.** There are 11,421 mentions of `c11h` in tracked files (207 files in
  `Sources/`), 316 references to `com.stage11.c11h`, and 233 distinct `C11H_*` names.
- **Secrets in history.** gitleaks scanned the 751 commits c11h has that c11 lacks and found two
  hits. Neither is a secret: one is a Cloudflare Access audience tag in
  `tools/friend-downloads/wrangler.toml`, the other a UserDefaults key name.
- **Private detail in history.** This is the real exposure:
  - 551 of those commits touch `notes/` or `docs/`.
  - 153 commit messages name Stage 11 hosts.
  - Tailnet addresses appear in four files.
  - 105 files contain the operator's home path. Public c11 already has 85 such files.

## Workstreams

Each one prepares; none publishes.

1. **Close the line.** Merge c11's last commit. From then on, c11h's `main` is the 2.0 line.
2. **Identity back to c11.** Rename everything that still says c11h:
   - the bundle, the app name and the CLI
   - variables, socket and state paths, and URL schemes (`c11h-show://`)
   - hc session names (`c11h-s1`) and the remote relay kits
   - the version, from `1.8.1-hN` to `2.0.0`

   Done when a 2.0 build passes the shareable gate and shows the user no "c11h".
3. **Migration.**
   - (a) The operator's own c11h state and live terminals move into 2.0 without losing a panel.
     It's proved in a sandbox guest first; the cutover on the operator's machine is Atin's go.
   - (b) A c11 1.8.x user's state and settings carry into 2.0.
4. **The update path for c11 users.** In a guest, prove two things:
   - Sparkle updates a 1.8.1 install, signed under Authentic Technologies, to a 2.0 build signed
     by Stage 11.
   - `brew upgrade` works.

   This needs Stage 11's Apple membership and notarization (C11H-179).
5. **First run for c11 users.** 2.0 adds hc, a background holder that keeps terminals alive after
   quitting. On first launch, users are told what it does and how to stop it (the 2026-11-02
   ruling: teaching starts now).
6. **A public tree.**
   - Move or scrub the operations notes (`<run-notes>/`) and the friend-download tooling.
   - Take out the tailnet addresses.
   - Check `LICENSE` and `NOTICE`. c11 forked cmux on 2026-03-18, while cmux was AGPL-only. cmux
     later moved to GPL-3.0-or-later (2026-03-30), and code cherry-picked from it since then can
     be combined with AGPL. The bundled hc is Apache-2.0.
7. **Docs and agents.**
   - The README stays in Atin's voice, and he signs off on any diff to it. The changelog gets a
     2.0 entry.
   - The c11h sidecar skill folds into the c11 skill.
   - `AGENTS.md`, `C11.md` and the vision (law 7, Decided 13) are updated, as are the references
     to c11h in Stage 11's `AGENTS.md` and the global instructions (with his OK).
   - The Lattice boards merge.
8. **Quality bar.** Fix C11H-248 (a 48.9 s freeze creating a terminal) and C11H-250 (a WebKit
   stall over 2 s on app switch), and pass C11H-82's restart proof.

## Atin's go, each

- Pushing to the public c11 repo.
- Releasing 2.0 to c11's users (Sparkle, the appcast, Homebrew).
- Cutting over his own c11h session.

## Open decisions

1. **The security bar for 2.0.** His ruling of 2026-10-31 says security is "fixed before c11h is
   released to the world"; the open items are hc's six limits and the gap on a linked machine.
   Recommended: 2.0 ships local persistent terminals on, and linking other machines behind an
   experimental switch that's off by default. The trust work then gates only that feature.
2. **History in the public repo.**
   - (a) Full history after the tree cleanup. c11 already publishes the same kind of material,
     and a straight fast-forward keeps every tool and agent working.
   - (b) One import commit, with c11h's private repo kept as the archive.
   - (c) Filtered history. This rewrites every SHA.

   Recommended: (a). It's needed only before the push.
3. **cbus in 2.0.** Settle it separately; it doesn't block 2.0.
4. **Who runs the prep.** Recommended: a fresh orchestrator on the c11h board, dispatched by the
   Chief of Staff.
