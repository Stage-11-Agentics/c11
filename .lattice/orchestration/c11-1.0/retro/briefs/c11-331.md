## The problem

Every new head creates `parent-<head>.bundle` with `git bundle create ... HEAD`, which carries the whole history (about 170 MB), and uploads it over a Hyperion to Atlas link measured at about 160 KB/s. Submodule bundles are SHA-cached already.

## Done when

- Staging a new head uploads only objects Atlas lacks: for example, an incremental bundle against a commit the Atlas cache already holds (`git bundle create ... <base>..HEAD` plus the prerequisite check on the far side), or Atlas fetching the head from GitHub when it is pushed. Pick the simpler design that keeps exact-head provenance (the built tree must equal the requested head; keep or extend the existing hash checks).
- A full bundle is still used when no shared base exists, and that fallback is tested.
- Unit tests cover base selection, the incremental path and the fallback, and go red without the change.
- One real staging run on Atlas from your worktree proves it: the upload size and staging time for a head whose parent Atlas already holds, compared with the old path. Use `--stage-only` or whatever flag stages without building or launching if one exists; otherwise a Debug build with no launch. Never launch the app.
- The c11-hotload skill says what the staging does now, in one or two sentences (the skill is the contract; do not run `scripts/sync-installed-skills.sh`, Cairn syncs after merge).
