# C11-551: Back after a jump

**Proposal for Atin, 2026-10-31 PDT. Owner: agent:C11-551-owner. Plan and HTML only; build awaits Atin's review.**

1. **Reuse one history.** Add a left-chevron immediately right of the new-workspace plus in `TitlebarControlsView.controlsGroup`. Invoke the existing `FocusHistoryStore` used by **History → Back / Forward**. Recommend retaining its **app-wide** trail, including cross-window returns; the ticket's per-window sketch would split an existing contract and strand cross-window link returns. Every window shows the same trail. No second stack or new persistence file.

2. **A step is a different (workspace UUID, panel UUID) destination.** Native panel/workspace links, Feed **Open**, attention jumps, and sidebar workspace clicks qualify; a workspace-only jump resolves to its focused panel. Clicking the same destination, hovering, opening the Feed popover alone, scrolling, typing, and browser-page Back do not. Ordinary panel/area selection keeps the existing one-second visible-visit rule. Hidden/background changes do not count; visible same-workspace agent focus retains today's seen-history behavior, without gaining operator-jump authority.

3. **Make immediate return work in that same model.** Today `prepareForNavigation` drops subsecond visits: after A → B, immediate Back can skip A or fail. Proposed small change: successful explicit operator jumps checkpoint the departing and arriving endpoints into the existing model, irrespective of dwell; Back/Forward finalize the currently visible endpoint there too. Deduplicate the current endpoint; traversal never appends itself; a fresh jump after Back discards the forward branch. Failed/no-op jumps add nothing. Keep measured dwell honest, including zero, and retain such checkpoints on restore. Automatic incidental visits retain the one-second threshold. Derive disabled state, tooltip destination, and navigation from one shared, nonmutating preview of this model, accounting for the open visit; do not use `back_count` alone.

4. **Bounded and recoverable.** Keep the existing **200-entry cap**, UUID reconciliation, and session autosave. Prune closed panels/workspaces and continue to the nearest earlier live, distinct destination. Resolve moved panels at their current location. Never reopen a process. If none remains, keep the button in place, disabled, with “No previous location.” A destination that closes between hover and click is reconciled again before navigation. Forward remains in the existing menu; no second titlebar button in this slice.

5. **Control and keyboard.** Use the existing titlebar button geometry/style and theme tokens; reserve its slot even when disabled. Accessible name “Back”; tooltip “Back to {panel} · {workspace}” plus the configured chord; keyboard focus ring. Reuse **History → Back / Forward** and the existing configurable actions. Proposed defaults: **⌘⌥[ / ⌘⌥]**, preserving saved bindings and explicit unbound choices. Current defaults are unbound. Browser **⌘[ / ⌘]** and workspace **⌃⌘[ / ⌃⌘]** stay assigned to their existing actions.

6. **Operator authority; agent observation.** Only native button, menu, and physical shortcut paths receive operator navigation authority. Preserve socket focus policy: agent history commands may focus within a selected workspace but cannot switch workspaces or raise windows. Observe through existing `c11 history --json --limit 200` / `history.list`: UUIDs, live titles, cursor, counts, measured dwell. These counts describe the stored trail, not a promise of navigability. Persist no titles, URLs, prompts, or content. Update the history skill reference for checkpoints/defaults if implementation is approved.

**Implementation acceptance, owner after GO:** A → link B → immediate Back → A → Forward → B; repeat via Feed, attention, sidebar and another window; same-target/no-op adds nothing; new jump after Back removes Forward; closing/moving a destination resolves safely; 201 steps cap at 200; zero-dwell checkpoint restores; button/menu/shortcut agree; no socket workspace switch. Native proof belongs in an authorized Atlas guest. This prototype proves only the proposed control and interaction, not those native paths.
