# C11-219: reloads.sh: launch staging in socket automation mode with the QA flag, and scrub C11_SURFACE_ID/WORKSPACE_ID from the app env

Found during the 0.65.1 staging smoke (2026-09-11). (1) A Release staging app has fresh defaults, so socket control comes up in c11-only ancestry mode and every CLI call from outside that instance fails with 'Failed to write to socket'; the orchestrator had to relaunch by hand with C11_SOCKET_ENABLE=1 C11_SOCKET_MODE=automation. reload.sh already passes these for dev builds (line ~500); reloads.sh should too, and honour C11_QA_LAUNCH the same way launch-tagged-automation.sh does. (2) reloads.sh's OPEN_CLEAN_ENV unsets the CMUX_* and C11_TAB_ID/C11_PANEL_ID vars but not C11_SURFACE_ID, C11_WORKSPACE_ID, C11_SURFACE_NUM, so a staging app launched from inside c11 inherits the launcher's surface identity (verified with ps eww). Add them (and their CMUX_ twins) to the list in reloads.sh and reload.sh.

## Plan

1. Update `scripts/reloads.sh`'s staging launch environment to scrub the complete C11/CMUX surface identity set while preserving the script-owned socket paths. Launch the Release staging app with `C11_SOCKET_ENABLE=1` and `C11_SOCKET_MODE=automation`, and forward the QA launch value with the same primary/legacy semantics as `QALaunchPolicy` and `launch-tagged-automation.sh` so `fresh` suppresses both startup modals and `resume` remains an explicit opt-in.
2. Add the missing `C11_SURFACE_NUM` and `CMUX_SURFACE_NUM` entries to the existing clean environment lists in `scripts/reloads.sh` and `scripts/reload.sh`, retaining each script's deliberate tag-specific socket assignments and existing dev behavior.
3. Leave `scripts/reloadp.sh` unchanged: it is the untagged production Release launcher, has no isolated staging socket or tagged QA mode, and changing it would broaden the production launch contract beyond C11-219.
4. Update `skills/c11-hotload/SKILL.md` to document that tagged staging sockets are externally reachable in automation mode and how the staging launcher carries `C11_QA_LAUNCH`; do not sync installed skills.
5. Validate shell syntax and, after the required provisioning, run one lock-wrapped Release staging build from inside c11 with inherited identity sentinels. Prove the tagged socket answers `c11 ping` and `c11 tree` from outside the staging instance, startup dialogs are suppressed, and `ps eww` contains none of the scrubbed identity variables. Quit the staging app and remove its DerivedData. Report the exact commands, timings, and any `reload.sh` validation limitation; then commit, push, open the PR, and wait for green CI.
