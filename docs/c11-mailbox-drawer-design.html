SETTLED

  1. Unread = the agent has not taken it (still in the inbox root, not in _read/). Operator-opened state is not tracked in v1.
  2. Bar renders when the panel has a description, a mailbox.address, or any mail. Zero shows a dim 0.
  3. Placement: description (truncates) · mailbox cell (fixed) · expand chevron.
  4. Live updates from the app's own delivery, push and receipt paths; a 60 s reconcile for panels on screen; bodies read only when the drawer opens. No file watchers.
  5. Received only in v1; Sent is a follow-up ticket.
  6. Feed of full messages, newest first, bodies over about 12 lines fold behind "Show all".

OUR ASSUMPTIONS (SAY IF ANY IS WRONG)

  • Bodies and body_ref files render as plain text in a non-editable text view. No Markdown, no links, nothing loaded. body_ref reads only regular files, at most 64 KB (then "truncated"), never FIFOs or devices, off the main thread. Missing, unreadable, too large and not-text each get their own plain sentence.
  • Read-only: no compose, reply, delete or mark-read. Opening the drawer never claims mail, so it cannot steal a message from the agent.
  • The drawer reuses the panel sheet's presenter. That means making it public in our Bonsplit fork and bumping the submodule (pushed to Bonsplit main first, per the repo rule).
  • Sender line resolves the from string to a live panel (number and address) when it can, and says "not open" when it cannot. in_reply_to becomes a chip that scrolls to the parent when that message is in the list.
  • _read/ is never pruned today, so the drawer shows the newest 200 and says how many older ones exist.
  • Localized strings, skill and mailbox guide updated, tagged-build computer-use validation including opening and dismissing the drawer.
