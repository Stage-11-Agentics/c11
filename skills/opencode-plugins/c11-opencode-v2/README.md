# c11 OpenCode 2 TUI plugin

This local plugin is loaded per OpenCode 2.0.25 TUI by `Resources/bin/opencode`. It uses the TUI's own current route and loaded session record to capture the exact displayed root. Capture is sent directly from the TUI process over c11's Unix socket; c11 verifies that the wrapper's claimed TUI PID is the foreground process-group leader for that terminal and that the socket peer is its descendant. The wrapper claim records the TUI's `HOME`, `XDG_DATA_HOME`, and `OPENCODE_DB` for crash recovery; explicit empty and in-memory database overrides remain unverifiable and never fall back to another store. A tool subprocess inheriting the shared server's `C11_PANEL_ID` cannot claim a displayed route or register the native OpenCode mailbox stream. Generic conversation pushes cannot forge claim metadata or replace an authenticated v2 route. A restored PID marker is not live authentication; the TUI must make a fresh claim before it can capture. The plugin does not load into the shared server and does not read or write OpenCode tenant configuration.

Before launching an explicit `-s`/`--session` resume, the wrapper creates a 120-second c11 reservation (the socket caps reservations at five minutes). The plugin captures only after `data.session.get(id)` returns the displayed row and that row has no parent. Capture is atomic in c11; another panel's exact ID or unexpired resume reservation rejects a conflict. When the UI route changes, the plugin first marks the old exact binding unbound; child and unhydrated routes stay placeholders, so typed fallback waits for a verified root. A conflict rejects with `session_conflict`; c11 holds the affected envelopes until a new route is captured.

Native delivery sends the fixed c11 invitation through `client.session.promptAsync`, then waits for matching user-message and text-part events from that exact session. Invocation alone does not acknowledge. Busy/retry, permission/question, child, unresolved, route-change, and ownership-conflict states cannot open a different session. A busy rejection stays buffered and uses a named `not_ready` failure; when the displayed session becomes ready, the plugin replaces its native registration so c11 can retry the same invitation. The final typed fallback gate also rereads OpenCode identity immediately before any terminal input. The plugin never reads or edits the composer.

The v2 adapter provides exact root capture and native mailbox confirmation. `C11_OPENCODE_NATIVE_MAIL_DISABLED=1` disables only its native stream; the adapter still captures and invalidates route identity so typed fallback is safe for a bound root and held for a child, pending or conflicting route. A route conflict remains held out of typed delivery even when native stream registration fails, and the same route is retried until ownership clears. It does not report lifecycle/status, prompt-cache, or permission-notification telemetry. v1 keeps its existing server plugin and TUI integration; unknown OpenCode versions receive no plugin injection and retain typed fallback. Generic c11 commands invoked by shared-server tool subprocesses may still use inherited caller-panel environment; this adapter does not use them for identity or mailbox ownership. See [the mailbox guide](../../../docs/c11-mailbox-guide.md#opencode-plugin-compatibility) for the feature matrix and residual.
