# C11.md: c11 2.0

The c11 project file: the mission and working notes for every agent on this tree, on any harness.
This tree was c11h until 2026-11-13 and is now c11 2.0 (Decisions 1-3 below); the Mission and the
rulings keep the name c11h as Atin said them. It adds to `AGENTS.md` (how to work in this code) and
`docs/c11-vision.md` (the goal and its laws) and never repeats them. Atin sets the mission; the
Chief of Staff and the project's Lead keep the rest current.

## One line, one repo

c11 1.x's last commit merged into this line on 2026-11-13 (C11H-264), and 2.0 became public
c11's `main` on 2026-11-18. Since 2026-11-28 there is one repo: this tree is developed on public
c11's `main` through PRs, the private development repo is archived read-only with its
commit-by-commit history, and the `stage11/c11h` board is read-only (`AGENTS.md`, Repo). The
`// c11h:` comments still mark where this tree departs from cmux and from c11 1.x.

Every release run records its time (Atin's standing rule: every build and pipeline is timed).
`c11-release.sh` and the friend publisher (`friend-downloads/publish.py` in the private c11-ops repo) each append one JSON line to
`release-timing.jsonl` beside the zip (the release folder on the build host): seconds per step
(build, stage, sign, notarize, staple, zip; verify, shareable, upload, flip), the total, the
failed step, and for a build the build host's own slot wait and compile time.
`scripts/c11-release-timing.py --ssh <build-host>` prints it in local time. A release report quotes it.

## Rulings and autonomy

- Lowered security is acceptable for the prototyping build, and is fixed before c11h is released
  to the world (Atin, 2026-10-31 15:53).
- Every milestone ends in something Atin uses, and in his call to continue or stop (vision, law 9).
- **c11h is private, invite-only pre-release software** that Stage 11 is building (Atin,
  2026-11-03 20:30). Stage 11 may hand it to a few people; there is no "friend build" track
  and no public release. Other things may come around it later. Superseded for 2.0 by
  Decisions 2 and 3: open source, public on his go.
- **The main production build stays shareable at all times.** Nothing lands on `main` that
  would stop Atin handing someone the current build, unless he consciously overrules for that
  change (Atin, 2026-11-02 18:44). The repo itself stays private. Superseded for the repo:
  c11 is developed in the public repo (2026-11-28).
- **Teaching starts now, not at release.** People must learn that their terminals run in
  different places; the "What's different in c11h" work is built now (Atin, 2026-11-02 18:44).
- **Before anyone outside gets a build** (Atin, 2026-11-03 15:50 and 19:38): c11h is signed
  and notarized as Stage 11 (C11H-179); Authentic Technologies is no longer used for
  notarizing c11h. After that, every build cut from a green main is notarized under a standing
  go. The relay's same-user trust is replaced (C11H-176, done); the remaining gap on a linked
  machine is documented, and closing it (C11H-71 plus per-client checks in hc) gates nothing.
  The download page (C11H-177) stays behind Access; when a build is first handed out, an
  unlisted page links to it. Problems go to Stage 11. The shareability
  check blocks, and one GitHub Actions Linux job runs it. c11h's welcome terminal starts Claude
  without `--dangerously-skip-permissions`; public c11 keeps the flag, a separate call.
- **c11h updates itself through Sparkle**, as c11 does (Atin, 2026-11-03 20:30; C11H-178).
  In 2.0 that is c11's own feed and key (`docs/c11-2.0-identity.md` §6), so C11H-178's separate
  feed is not built.
- **c11 is retired; Atin works only in c11h** (Atin, 2026-11-04: "We have since retired C11 and
  are now only in C11H."). Settled by Decision 1: the c11 line closed into this one (C11H-264).

## Decisions

Atin, Fri 2026-11-13, about 1:40 PM, in the C11H Strategy panel. The prep plan is
`docs/c11-2.0-plan.md`.

1. **c11h becomes c11 2.0, and the c11h name retires.** "For now, I think we just call it C11
   2.0. We may choose to rename, but we might as well just bring this all back into C11 2.0. ...
   I think we can get rid of C11H and instead just have this be C11 2.0." A later rename (such
   as 11mux) stays open. This answers "Does c11h eventually consume c11?" and the 11mux plan's
   D7, and supersedes the vision's Decided 13 ("separate for now").
2. **It stays open source.** "I do think that we're probably going to keep this as open source
   for now."
3. **Prep only: nothing goes to GitHub publicly until his go.** "Don't actually push it live on
   GitHub yet though, but let's just prep to do this." The c11h repo stays private; pushing to
   the public c11 repo, and releasing 2.0 to c11's users, each need his named go.
4. **Licensing and contact for 2.0** (Atin, Sun 2026-11-15 22:44, via the 2.0 decisions seat;
   C11H-345). "One, great. Two, minimal but fine. C, copyright line. Yeah, we don't even need to
   say that. C11 is stage 11 agentics Period contact email Let's do hello at stage11.ema. G
   alright sounds good." AGPL-3.0-or-later stays; NOTICE carries one short paragraph on the cmux
   code picked after cmux's GPL relicense and the copyright line "Stage 11 Agentics";
   Stage 11's hello address is the security and conduct contact; the welcome terminal starts plain
   `claude`, never `--dangerously-skip-permissions` (C11H-130).
