## Change

Modify `Sources/ContentView.swift::WorkspaceMountPolicy` and `reconcileMountedWorkspaceIds` to distinguish selected/retiring handoff IDs from pending background loads. Our fixed normal-operation background allowance is **one**. Preserve the selected workspace and at most one genuine retiring handoff; admit one additional pending workspace outside those IDs. Thus normal bounds are two bodies, or three while a real handoff pair exists; after priming/handoff settlement return to the existing one-body steady state. Do not compute this bound from pending count.

Select admitted pending IDs deterministically in existing workspace order, retaining an already admitted live pending ID until completion/timeout. Only admitted IDs pin a background mount. Keep all remaining pending IDs in the model; never cap the creation request set or reject/drop a launch. Completion/removal/timeout causes the existing pending publisher to reconcile and admit the next ID. Pass the emitted pending set through reconciliation: @Published emits before the backing property changes, so rereading it can leave a completed ID admitted. Pass emitted debug pins too so fixture retention stays accurate. Ensure an old completed background body cannot consume the freed slot instead of the next pending ID. Selection and handoff deduplicate against admitted background IDs.

Reuse existing prime/headless-start functions unchanged where possible. A direct send to any unmounted sibling uses its existing bootstrap demand path without requiring SwiftUI mount; a read does likewise after C11-296. If slot ownership needs explicit bookkeeping, keep it in the mount policy/ContentView and only minimally adapt `WorkspaceManager` request/complete wiring; no second terminal lifecycle. Explicit debug mount-retention overrides stay separately labeled test infrastructure, never included in the production pending allowance; acceptance runs with that override off. Do not silently break a debug harness by truncating its requested fixtures.
