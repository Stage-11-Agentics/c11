# Markdown viewer prototypes — shared brief

Ticket: C11-336 (post-1.0). c11's markdown tab today renders with MarkdownUI (native SwiftUI): live reload, font scale, Mermaid via an external CLI that may be missing, per-block text selection only, no find, no outline, no code highlighting, weak dark theme. Decided: it moves to a **WKWebView renderer**. Editing is out of scope (C11-344); a **read-only source toggle** is in.

We are prototyping three directions, each resting on a different core assumption about what the markdown tab is *for*. Each is a clickable HTML prototype. They must differ as UX paradigms, not colorways.

## Who uses it

The c11 operator: one person running 8 to 30 agents in parallel, panes split across a screen. Agents write plans, specs, audits and trail files to disk and open them in a markdown tab beside their terminal (`c11 markdown open plan.md`). The operator arrives at a tab cold, between other agents, and needs to get the gist fast. Panes are often narrow: half or a third of a laptop screen.

## Shared requirements (all three)

- **Self-contained HTML** at `docs/design-prototypes/markdown-viewer/<direction>/index.html`. It must work opened from `file://` (no fetch of local files: embed the fixture markdown inside the page, e.g. `<script type="text/markdown" id="doc-…">`, generated by a small script if convenient). Libraries from cdn.jsdelivr.net are fine: markdown-it (+ plugins for footnotes, task lists, anchors, GitHub callouts `> [!NOTE]`), mermaid, highlight.js, KaTeX. This mirrors what the real build would bundle.
- **Real content, not lorem.** Fixtures are in `docs/design-prototypes/markdown-viewer/fixtures/`, copied from the repo: `c11-messaging-primitive-design.md` (740 lines, a big Mermaid graph, wide tables with long cells, code), `c11-mailbox-guide.md` (anchor links), `agent-browser-port-spec.md`, a Lattice plan `task_01KYMTXQVWCXCF0TGN5ZWG341E.md` (task lists), `c11-markdown-SKILL.md`. Render them through the real renderer. Ugly real data is the point: long tables, deep headings, a giant diagram.
- **Framed as a c11 area**, not a browser page: a c11-style tab bar on top (tab number + title, a count cell `● ⌄ N` at the right), a one-line description bar under it, then the markdown surface. A control outside the frame (top of page, clearly prototype chrome) toggles **pane width: narrow 560px / medium 820px / wide 1200px**, and **light / dark**. The design must hold at 560px.
- **c11 house look** for chrome: the void language in `docs/design-prototypes/c11-reskin/` (near-black surfaces, hairline rules, JetBrains Mono / SF Mono for chrome, one gold accent `#c9a84c` used sparingly). Prose typography is yours to decide per direction (a reading face is allowed and encouraged where it serves). Both themes must look deliberate; dark is the one that is weak today.
- **Every direction has:** Cmd+F find with match count and next/prev; a read-only source toggle; syntax-highlighted code with copy; Mermaid rendered inline (theme-matched); wide tables that do not break the layout; heading anchors.
- **Agent-native seam:** show how an agent drives this surface. Include a small, collapsible "agent CLI" drawer (prototype chrome) listing the `c11 markdown …` commands this direction implies (e.g. `c11 markdown scroll --tab tab:12 --heading "Send flow"`, `c11 markdown visible --tab tab:12 --json`), and make at least one of them *demonstrable*: a button in the drawer that simulates the agent running it and the surface responding.
- **Persistent `PROTOTYPE` badge** on screen, part of the page.
- **UI never jumps**: fixed-width toggles, reserved space, tabular numerals.
- Interactive elements in English, c11 voice (`docs/c11-voice.md`): lowercase chrome, forward verbs.

## Validate before you report

Open the page with the Playwright MCP tools (headless; do not put windows on the operator's screen and do not open c11 tabs). Check: zero console errors, Mermaid renders, find works, each width and both themes look right. Take screenshots at 560px and 1200px in both themes into `docs/design-prototypes/markdown-viewer/<direction>/shots/`. Fix what you see. Then report: what you built, the design choices that matter, what you would push further, and anything that fought you.
