## 0. Shipped, and small fixes found along the way

**Shipped:** PR #490, merged as `0ff8887e5e`. It closes a hole where a host opened with `c11 ssh` could run commands on your Mac. The remote shell still works; remote `c11` commands are refused. It goes out with the next release. The repo is public, so its wording is neutral.

**Small bugs the research found (D25):**

1. **Claude hooks wipe the whole workspace's waiting state.** One Claude starting a tool clears every sibling agent's notification in that workspace (`CLI/c11.swift:16372, 16454, 16562`). With six agents in a workspace, this happens constantly.
2. **Flags never reach the menu bar extra.** The skill says they do. The code reads only notifications (`Sources/AppDelegate.swift:13450-13493`). Found independently by two research tabs.
3. **Questions and plan approvals in bypass mode never mark the tab as waiting.** Claude fires no Notification hook for them under `--dangerously-skip-permissions`. Inferred from cmux's evidence, with high confidence.
4. **The Notification Command hook carries no workspace or tab IDs,** and still uses `CMUX_` variable names.
5. **c11 writes a plugin file into OpenCode's config** (`~/.config/opencode/plugins/`), outside the wrapper rule. The wrapper already loads it per process, so it may load twice.
6. **`c11 claude-teams` hands Claude an ignored SIGPIPE** (`CLI/c11.swift:17639`).
7. **Skill and doc drift:**
   - `metadata.md` says `activity` isn't persisted, but it is.
   - `events.md` says `seq` starts at 0, but it starts at 1.
   - The skill's `c11 ssh` text contradicted what shipped. #490 fixed that part.

**Housekeeping:** your local c11 `main` checkout is 34 commits behind `origin/main`, and it holds uncommitted `.lattice/` changes from another agent's run. I haven't touched it.

## 1. Event journal (report 01)

**Today:**
- "Waiting" just means the tab has an unread notification.
- "Finished" and "needs your answer" look the same.
- Codex shows working whenever you press Return.
- Grok, Kimi and Copilot show working for their whole lives.
- Nothing orders events across hook processes, so a late event can leave a finished agent stuck on "working".
- Waiting is lost on restart, and there is no history.

**Proposal:**
- Every lifecycle event goes, in order, into one append-only file that c11 writes.
- A small pure function turns that record into working, waiting (with a reason), idle or error, for each agent.
- The vocabulary matches cmux's, so future comparisons stay cheap.

**Feeding it without writing any agent config:** hooks are passed at launch only.

| Agent | Source |
|---|---|
| Claude | More hooks in the launch-time `--settings` file |
| Codex | Hooks via `-c` flags with Codex's own hook-trust bypass, plus a canary (D2) |
| OpenCode, pi | Existing plugins, re-pointed at the journal |
| omp | Its `--hook` flag |
| Gemini | Planned: a new wrapper |
| Grok, Kimi, Copilot | Transcript reading (D4). c11 already reads those transcripts every 10 seconds for the tab clocks |

**What it unlocks:**
- The Feed (section 2) gets "blocked on what".
- Overwatch gets "who is blocked, for how long" from one file instead of screen scraping.
- The tab clocks become accurate and survive restart.
- Restore learns which sessions were live when c11 died.
- `send` can refuse to type into an agent that's blocked on a dialog.

### 1.4 Guardrails against a repeat of C11-188 (D1)

- Every requirement names a real incident: a finished agent stuck on working, waiting lost on restart, or permission confused with stop.
- Tests replay recorded real hook sequences from tagged builds.
- One ordering rule, the writer's sequence number. No epochs, fences or transactions.
- The review-cycle cap is a hard stop.

| Phase | Content | Size |
|---|---|---|
| 1 | Vocabulary, store, append verb, fold, replay; today's signals mapped in; blocked split from finished | M |
| 2 | Wider producers: more Claude hooks, Codex hooks with canary, Gemini, omp, transcript events | M |
| 3 | Consumers: per-tab `lifecycle.changed` events, an agents snapshot verb, clocks, restore list, skill | S to M |
| 4 | Screen observation for agents with no hooks | M to L; can trail 1.0 |

## 2. Feed (report 03)

**What cmux has:** one list of "an agent is blocked on you" items across every workspace. It shows as a sidebar mode, a keyboard TUI and actionable notification banners. Answers go back to the agent through hook JSON. It is off by default, behind a Beta toggle.

**The fact that reshapes it for you:** most of your agents run in bypass mode. Permission prompts never happen, and cmux's decision bridge then delivers nothing for questions or plans. What actually reaches you is questions, plan approvals, finished turns and flags.

**Proposal:**
- **What it is:** a view over what c11 already knows, not a new store. Each tab has at most one open "ask" (question, plan, permission, input, or a flag), because a TUI agent can only block on one thing at a time.
- **Answering:** c11 re-reads the screen, confirms the prompt is still there and nothing is half-typed, then types the answer. If either check fails, it jumps you to the tab instead of typing. Menu keys live in a small per-agent table, with screen fixtures from real sessions.
- **Where it appears:** a ⌘I quick view, a `c11 feed` command, and notification banners with buttons and text replies.
- **Flags:** a flag is a Feed row. Replying to it sends the text and lowers the flag with the answer attached.

| Phase | Content | Size |
|---|---|---|
| 0 | The three bugs in section 0 (workspace-wide clear, bypass questions, menu bar flags) | S |
| 1 | Typed ask per tab, `ask.opened`/`ask.closed` events, `c11 feed list/answer/open/watch` | M |
| 2 | Quick view, ⌥V unified with the Feed order, menu bar flags | M |
| 3 | Verify-then-type answering: Claude menu spike, fixture table, fall back to jump | M |
| 4 | Banners with buttons and text input | S to M |
| 5 | Codex, omp and Gemini attention hooks | S to M |
| 6 | Screen classifier for hookless agents | M |

Phases 0 to 2 alone give you a readable cross-workspace list with jump, at low risk.

**Try cmux's Feed today:**
1. Open a terminal in cmux.app, not c11.
2. Turn on Settings › Beta Features › Feed.
3. Run `claude` without bypass mode.
4. Open the Feed with ⌘⌥B then ⌃4.
5. Never run bare `cmux hooks setup`: it rewrites the Codex, Gemini and OpenCode configs with no backups.

## 3. Agents on remote hosts (report 02)

**What cmux built:**
- **#14902:** Claude and Codex on a remote host report status to the local sidebar. It installs hooks into the remote agent's config, which c11 won't do.
- **#14959:** `cmux session move` moves a stopped session (transcript, memory, git tree) between Mac and host.
- **cmux-tui:** a headless Rust server that owns sessions so they outlive the app.

**Proposal: evolve `c11 ssh` (option A).**
1. **Terminal holder:** c11's Go remote daemon holds the agent's terminal on Atlas, so the agent survives a lid close. The code is harvested from cmux's Go daemon (D10).
2. **One link per host:** commands from the remote travel over the ssh link the Mac already holds. No reverse port forward and no token file on the host.
3. **Deny by default:** a remote tab may only report about itself (`set-agent`, `set-status`, flags, its own mailbox). It can never `send` to other tabs or open windows. This is the rebuilt version of what #490 just turned off.
4. **Tab-level host (D9):** `launch-agent --host atlas` and `new-split --host atlas` fall out of it. That is what an orchestrator on Hyperion needs to place a delegator on Atlas.
5. **Restart:** reconnect and reattach. If the holder is gone, type the stored resume command.
6. **`c11 move <tab> --to atlas|local`:** stopped sessions only in 1.0.
   - It handles your per-call-sign config directories.
   - It handles Atlas's different username (`atinwoodard`).
   - It keeps a rollback ref if the copy fails.
7. **Doctrine amendment:** c11's own directory on a connected host (`~/.c11/`) counts as "c11's bundle" for the wrapper rule.

**Overwatch:**
- A Prime box could get the same one-tab channel over `prime sandbox ssh`. That's outbound only, so the box still never joins the tailnet. Boxes would get report verbs only: no mailbox and no `send`.
- Seats could then raise flags and set status directly instead of through the PR-label poller.
- `seat-attach` stays for 1.0.

| Slice | Size |
|---|---|
| Smoke-test today's `c11 ssh` against Atlas | S |
| Persistent terminal holder in the daemon | M to L |
| Command channel over the ssh link | M |
| Scoped, deny-by-default dispatch on the Mac | M |
| Remote CLI verbs and wrappers | M |
| Host-aware status, "link down" state | S to M |
| Persistence and reattach | M |
| Per-tab host model | L |
| `c11 move` (Claude, then Codex) | M + S |
| Prime transport override for Overwatch | S |
| Federation | XL, after 1.0 |
