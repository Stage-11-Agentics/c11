hc, c11h and the bus

The whole picture of what runs for c11h today, what it becomes at the end of each milestone, and why. Three layers: hc runs terminals on each machine; c11h is the window and the agent layer; the bus carries agent messages between machines. Every claim carries a source tag; the tags resolve in zone H. Where sources disagree, the page says so instead of picking.

01hcherdr-core, herdr's open terminal runtime (Rust, Apache-2.0). Stock upstream release 0.1.16, built and signed by us, never patched. Per machine and session: a core (the socket, one Ghostty VT screen per terminal) and a holder (owns every PTY, keeps a 1 MiB tail, restarts a crashed core after 3 s). Cores reach other machines over SSH with hc machine add.Terminals and the agents in them keep running when the app quits, crashes or updates, and a terminal on the build host arrives like a local one, without writing our own daemon.V law 1, 6, 8 · CORE §shape · V D12
02c11hA separate macOS app forked from c11 (com.stage11.c11h), with hc underneath. It talks to one hc socket on its own machine and owns everything the operator sees and every piece of agent state: metadata, descriptions, flags, delegates, mailbox files, journal, lineage. None of that lives in hc.c11's experience is the floor, not the ceiling; c11 itself stays untouched as the daily tool until c11h earns its place (Decided 13: separate app for now).V §vision, law 7 · CORE §mapping · V D13
03the busConstellation Bus: one small published message core (Rust, SQLite per copy, replicate-and-merge, a Cloudflare Durable Object as the cloud copy), run standalone by Stage 11 and, at some later point, bundled by c11h on every host. Planning only, no code, by Atin's hold of 2026-10-18."Say it once, from anywhere. It arrives, or someone finds out": mail with receipts that keeps working when any machine is down. 03Agent messages and flagsLocal: c11's mailbox files, flags and metadata under c11h's own state on the laptop. The build host: the c11 relay shim takes a slot (c11h.relay.r00…r31) in the build host's hc document store by compare-and-set; the doc event crosses the link; c11h on the laptop verifies the caller (C11_PANEL_ID must own the terminal with HC_TERMINAL_ID) and runs the request. Fail fast at 1.5 s; telemetry spools (256 records); mail is marked ext.c11h.relay. Allowed: reads, metadata, status, flags, mail. FGlossary
NameMeansSource
hcherdr-core, said "Herder Core": herdr's open terminal runtime (Rust, Apache-2.0). One core per machine and session, a holder that owns the processes, machines linked over SSH.V §names
coreThe hc process that owns the Unix socket, keeps each terminal's screen (one libghostty-vt per terminal), the event stream, labels, status and the small document store. Can crash, restart or update while programs keep running. One per session.CORE §shape
holderThe hc process that owns every PTY in a session and keeps a 1 MiB raw tail per terminal. Started with the first terminal; restarts a crashed core after 3 s; if it dies, every program in the session dies. Older holders drain after a core update, so an "orphan" holder with live terminals is normal.CORE §shape · CS
sessionOne named hc world: its own socket, core, holder, state directory (~/.local/state/herdr-core/<session>). c11h uses c11h (dev builds c11h-<tag>); herdr-app uses default. Never shared.C L1 · V §separation
shardOne of the several hc sessions c11h spreads its terminals across (c11h-s1…sK), each its own core, holder and parse thread, so a holder loss or an output flood touches one shard. Placement sticky by workspace. Identity is (owningCoreID, address) because addresses restart at t1 in every shard.V D12 · SHC
link / machineAn SSH connection one core holds to another machine's core (hc machine add, far end hc connect --session …). Terminals there arrive as studio/t7. Rooted in the viewer: hosts never dial a laptop. c11h names the exact remote binary through atlas-via.sh.CORE §shape · P T11 · B9 §3
herdr / herdr-appherdr: the company (YC F26) and its terminal multiplexer TUI (not on hc). herdr-app: herdr's desktop client on hc, the nearest competitor; installed on the laptop as a reference, with its own default sessions on both machines.V §names · CS
relayc11h ticket 14 (C11H-16): the c11 shim in a build-host c11h terminal that reaches c11h on the laptop through hc's document events over the existing link, while the laptop is awake. Prototype trust; replaced in Milestone 2.R · P S9
bus / cbusConstellation Bus, CLI cbus: the message and event backbone (mail with receipts, topics with retained values) that works with any machine down. One published core; Stage 11's wiring private.B C11 · PH
postmasterThe bus's per-host delivery process that writes into the local last mile (c11's outbox, hc terminal.send … if: idle, or a guarded tmux paste on a box).B9 §terms
censushc-census: one stdlib Python file that reads the process table, binary hashes and state files (never connects to a core) and writes one hc.instance.v1 record per (node, session); the laptop pushes to the build host; the Seat Census serves /hc.json. Flags version skew, orphan holders, holder loss.CS
pinThe one hc build c11h runs, by SHA-256, verified at every connection: today 0.1.16, binary c617feeb…. Moves only through a pin-bump ticket that passes the contract suite.C L2 · HC
contract suiteC1 to C14 in the hc repo: what c11h relies on in hc (launch tuple, inherited env, RPC methods, event framing, attach stream, child-end semantics, direct-child TCC, holder recovery, link handshake, ancestry, addresses, headless size, update path), run against a candidate binary in a throwaway session.C2H
RecoveredThe c11h workspace where orphaned hc terminals from c11h's own session land for Atin to close; c11h never kills them.P S7
c11h-coreC11H-37: a standalone utility for c11h's own hc core (list, attach, jump to panel), built from Atin's prototype revisions.MS §where · ST 11:57
