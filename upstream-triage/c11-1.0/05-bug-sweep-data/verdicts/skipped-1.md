## Top findings

PR 10856 removes unnecessary observation of whole tab models when finding pane ownership. c11 still scans `tabs(inPane:)` at `Sources/Workspace.swift:9316` and reads selected Tab values in portal-facing views. This is directly relevant to known problem 2, the reported AttributeGraph storms. With 10-40 agents, title changes create repeated opportunities for unrelated view invalidation. The scale of that cost in c11 is inferred. Reimplement the identity-only lookup using c11's Bonsplit API.

PR 1837 replaces an area-based host handoff rule with explicit host identity and teardown handling. c11 still requires the replacement host to be 20% larger in the ambiguous case. A same-size pane move therefore need not win ownership while the stale host exists. This makes drag/drop and workspace churn a useful target for an adapted portal fix. It does not explain the [August 25 teardown deadlock](../../../../notes/2026-08-25-freeze-surface-deinit-deadlock.md).

PR 3429 adds recovery when a live terminal no longer has a registered main-window route. c11's manager lookup still depends on `mainWindowContexts`. The source paths exist, but a live terminal outlasting context removal is inferred. For days-long agent sessions, recoverability matters more than the modest implementation size suggests. PR 3150 separately confirms stale global-manager routing in sidebar controls. Keep these mechanisms separate when adapting fixes.

PRs 3152/4083, 7637, and 8168 address regular layout friction: the selected workspace is not revealed, tab strips recenter during resize, and AppKit can add terminal top insets beneath an existing tab strip. These are medium-priority fixes for a dense workspace layout. PR 5474's intrinsic-size ratchet remains probable because the AppKit trigger was not exercised.

The spot-checks preserve the highest-priority queue and rendering concerns, but correct two overclaims. PR 8793 addresses a renderer mailbox, distinct from the app mailbox in the recorded teardown deadlock. Its latest-value publication must not be reduced to dropping lifecycle updates. The grouped PR 2176/2183 confirmed use-after-free claim is unsupported as written. Neither this review nor the upstream diffs establish a cause for the unexplained July 28 deadlock.

## Spot-check

Three shared-confirmed bug rows were checked per source file. They are outside the 48-row counts above.

1. **render.md, PR 8793: confirmed hazard, important correction.** c11 `ghostty/src/Surface.zig:3336` pushes visibility with `.forever`; focus does the same at `:3352`. Its renderer mailbox is `BlockingQueue(renderer.Message, 64)` in `ghostty/src/renderer/Thread.zig:35`. The August teardown queue is the separate `BlockingQueue(App.Message, 64)` at `ghostty/src/App.zig:571`. The source verdict incorrectly calls them the same queue. Upstream cmux `162da350c4` references Ghostty fix `ca21db1bb8361bf5b58a848dd823b6ee24a5d9fa`, which uses atomic latest-value publication for visibility, focus, and display ID. Do not substitute `.instant` and silently drop visibility updates: losing the final visible=true can leave a surface hidden. High severity, M adaptation, reimplement the publication mechanism. This does not repair the recorded app-mailbox teardown deadlock. Blocking requires a full or stalled renderer queue; no hang was reproduced here.

2. **render.md, PR 1937: agree on the source defect.** Upstream merge `c9616c59e9` moves scrollbar, cell-size, color, and config UI mutations to the main queue in `Sources/GhosttyTerminalView.swift`. c11 dispatches the action callback directly at `Sources/GhosttyTerminalView.swift:1074`, mutates scrollbar/cell state at `:2161`, and applies colors/config at `:2281`. Off-main UI mutation remains possible. The reported macOS 26 black-frame symptom is upstream evidence, not a local observation. Copy callback-owned strings before asynchronous dispatch.

3. **render.md, PR 3048: agree on unnecessary portal rebind.** Upstream `0bdf69496a`, `Sources/GhosttyTerminalView.swift`, removes unread-ring changes from the rebind predicate. c11 retains `previousDesiredShowsUnreadNotificationRing != showsUnreadNotificationRing` at `Sources/GhosttyTerminalView.swift:10195` through `:10202` and binds at `:10213`. A ring-only change still performs the expensive structural operation. Frequent agent completion notifications make this relevant to known problem 2. The claim that every such rebind visibly blanks a terminal is not established by static inspection.

4. **perf-supplement.md, PR 2116: agree.** The [upstream diff](https://github.com/manaflow-ai/cmux/pull/2116/files) adds `scheduleTick` and `enqueueScrollbarUpdate` coalescing. c11 `Sources/GhosttyTerminalView.swift:1069` queues a new tick for each wakeup; scrollbar actions update and notify immediately at `:2161`. This is a credible contributor to known problem 2 under bulk agent output. Contribution to the observed minutes-long backlog is inferred. The upstream benchmark is not a c11 measurement. It does not remove the dependency cycle of the August teardown deadlock.

5. **perf-supplement.md, grouped PRs 2176/2183: disagree with the grouped confirmed use-after-free finding.** PR 2183's [diff](https://github.com/manaflow-ai/cmux/pull/2183/files) extends workspace lifetime after upstream changed to lightweight `WorkspaceCreationTabSnapshot` values. c11's `WorkspaceCreationSnapshot` retains actual `[Workspace]` at `Sources/TabManager.swift:1112`; that array is used after construction at `:1422` and assigned at `:1428`. The alleged missing retain is therefore not demonstrated: `n/a-diverged` for that lifetime mechanism. Applying a stale snapshot could still overwrite a reentrant close/reorder, but such a c11 trigger is inferred and is not the fix introduced by PR 2183. PR 2176 is a different change: its [body](https://github.com/manaflow-ai/cmux/pull/2176) and component commit `875b610d4b` replace an inherited C configuration with a font-size scalar. c11 still carries a C config through `Sources/TabManager.swift:1402`, `Sources/Workspace.swift:35`, and `Sources/GhosttyTerminalView.swift:2730`. However, its native producer at `ghostty/src/apprt/embedded.zig:959` duplicates the working-directory string into app-allocated storage; it does not establish the claimed source-surface-owned dangling pointer. For nondefault IO surfaces, callback/userdata lifetimes require a separate ownership check. The original combined high-severity confirmed crash claim should be withdrawn, not copied forward based on missing helper names.

6. **perf-supplement.md, PR 3355: agree, with an omitted failure mode.** The [upstream diff](https://github.com/manaflow-ai/cmux/pull/3355/files) sets accepted-client send timeouts and `SO_NOSIGPIPE`, then loops until the response is written or a real error occurs. c11's accept path at `Sources/TerminalController.swift:1758` only restores blocking mode and creates a connection thread at `:1852`. `writeSocketResponse` at `:1563` makes one unchecked `write`. Thus stalled readers can pin threads, and a short write can truncate a response. Both mechanisms are shared-confirmed; medium severity and S port. No process-killing SIGPIPE behavior was demonstrated. C11-211's autoreleasepool fix does not supply either timeout or complete-write handling.
