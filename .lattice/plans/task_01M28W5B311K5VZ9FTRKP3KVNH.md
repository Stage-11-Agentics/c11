# C11-211: Socket client threads pin autoreleased objects for the life of the connection (~3 GB/day leak)

handleClient serves each socket connection on a dedicated Thread whose root autorelease pool only drains at thread exit. A client that holds its connection open (Sekhem Prime, persistent since launch) pins every command's autoreleased Foundation objects (JSONSerialization parse/encode buffers, bridged strings) until disconnect. Field: prod c11 0.64.0 at 12.5 GB footprint after 6.4 days; heap census 146k NSConcreteData / _NSJSONWriter in lockstep, ~1/s, ~3 GB/day; leaks --traceTree shows the NSData held by @autoreleasepool pages rooted in a thread's TLS pool slot. Fix: drain a pool per read iteration in the connection loop, plus the accept loop and hang-monitor watchdog (the other forever-threads). Regression test drives the extracted loop over a socketpair.
